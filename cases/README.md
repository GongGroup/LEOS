# cases: all calculation data

One directory per chemical system; each subdirectory of a system is one calculation
(a run):

```
cases/<system>/<run>/
```

Each run has one row in [INDEX.tsv](INDEX.tsv), and each distinct structure has one row
in [STRUCTURES.tsv](STRUCTURES.tsv). Code finds data only through these two tables
(pyleos/cases.py) and never guesses from directory names. `python3 -m pyleos check`
verifies that the two tables agree with the directories (the unit test
pyleos/tests/test_registry.py runs the same check).

## Columns of INDEX.tsv

| Column | Meaning |
|---|---|
| case | system directory name: the chemical formula in lower case, brackets replaced by underscores, e.g. cr_co_6, srbe_oh_4 |
| run | run directory name, see the table below |
| role | purpose: bench74 (74-case benchmark), comas (Comas-Vilà comparison set), test-regression / test-homonuclear (held-out test set), clean-override (recomputation that the clean set uses instead), app-li2o2 / app-ceo2 / app-fe3o4 / app-cathode / app-methane (applications), legacy (recomputation of systems the old program failed on), corrected (recomputation on the correct structure, see pyleos/sets/corrected.json), variant (another setting of the same system), diag (diagnostics and recomputation), structure (structure only), v1-failed (produced no EOSCAR) |
| bench_set | group within the 74-case benchmark: v1_mol, v1_oxide, wave1, wave2; same as the batch column of the golden table |
| ref_key | key of the case in pyleos/sets/reference_os.json |
| origin | path before the change to this layout; maps paths in old documents and old logs back to the run |
| structure | id in STRUCTURES.tsv of the structure the run uses |

## Columns of STRUCTURES.tsv

Runs of one system whose cells match each other (pymatgen StructureMatcher, supercells
and relaxation differences allowed) share one row. A system with one structure uses the
system name as id; a system with several uses `<system>~a`, `~b`, ...

| Column | Meaning |
|---|---|
| composition, natoms, spacegroup | element counts (alphabetical order), number of atoms, spglib space group (symprec 0.1) |
| status | ok (the structure corresponds to a real compound or a well-defined model), suspect (in doubt), wrong (conflicts with the chemical formula or the known phase, or the geometry itself is broken), unchecked (not checked) |
| kind | registered (source, edits and sha256 are all recorded), database, literature, experimental-cif, hand-built, derived (derived from another structure), generated (generated by a script), legacy (carried over from early work), copy (copy of another system), unknown |
| confidence | verified (registered, or reproducible within this repository), phase-matched (the structure matches an experimental COD entry, which confirms the phase, but the entry it was taken from is unknown), inferred (only an inference made during checking), unrecorded (no record at all) |
| source, ref | description of the source; database id, COD id or DOI |
| edits, evidence | changes made to the original structure; files that support the conclusions above |
| note | known phase, checking notes, result of the COD comparison, separated by `｜` |
| members | runs that share this structure |

"The geometry itself is broken" means that the structure VASP actually reads has
coincident or too-close atoms (check uses a 0.5 Å threshold). When POSCAR uses Cartesian
coordinates, VASP also multiplies the coordinates by the scaling factor on the second
line; read the file by this rule when checking geometry.

## Run directory names

| Run name | Meaning |
|---|---|
| v1 | calculation with the project's early v1 program (greedy); v1-mol is used for ReO3, which has one run in the molecule set and one in the oxide set |
| v3 | standard calculation with the current patch (v3) |
| v3-recompute | recomputation for the held-out test set (gpuw90 wannierises again from the archived overlap matrices) |
| v3-scdm-only | SCDM-only fast mode, not counted in the comparison |
| v3-ispin2, v3-relaxed, v3-u, v3-md, v3-md2, v3-verwey | v3 variants: spin-polarised, relaxed lattice, +U, MD snapshots, Verwey phase |
| polaron-* | Li15O16 polaron tests (U values, PBE/HSE single points) |
| v31, v31-wp, v31-ghost, v31-mag*, v31-nowin, v31-abort2, v31-4gpu | recomputations and diagnostics with the v3.1 patch: with the #WP projection block, ghost A/B, initial magnetic moments, no win written, reproduction of the abort, 4 GPUs |
| w90-library, w90-offline | comparison of the wannier90 library mode and the offline mode |
| md-x0.00 etc. | Li-rich cathode MD: initial structure POSCAR, production log md.log, acceptance verdict.json |
| structure, structure-hand, structure-fixed | structure only: original structure with Bader analysis, hand-built structure, correct replacement structure (with SOURCE.md) |

The structure-correction recomputations (SAI: LEOS/recompute_20261021; VASP 6.4.3 +
LEOS v3.1, GPU build; the wave's INCAR template plus the magnetic moments and +U of the
original run) are also named v31. Their directories also hold a SOURCE.json, which
records the structure source, the edits and the sha256.

## Notes on the v1 data

The v1 data come from the project's early v1 program, which assigns with the greedy
rule. They are the source of the legacy regression set of the 74-case benchmark
(36 cases: 10 molecular crystals, 26 oxides and halides). Each oxide system originally
had several runs; only the one the benchmark uses is kept here. The other runs, and the
v1 runs of zno, na3vo4 and reo2, which never entered the benchmark, exist only in the
git tag `pre-reorg` (`git show pre-reorg:data/v1/oxides/...`). results/v1_oxide_runs.tsv
is the v1 summary table of that time. Its workdir column points to the latest run of
each system, which in most cases is not the run the benchmark uses; the table is a
historical record only.

The "status" in the v1 summary table says only whether the program finished and the
electron count is conserved, not whether the oxidation states are correct. For example,
As4S4 is recorded as OK although the oxidation state of S there goes as low as −8. The
v1 run of Ca3AuN lacks EIGENVAL and produced no EOSCAR. The cell of "co" actually holds
two ethylenedione molecules (O=C–C=O), not carbon monoxide; see
docs/testset_findings.md.
